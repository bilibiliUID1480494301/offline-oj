# 国赛级升级规划

> 面向当前 `offline_oj`（v2.0.0，测试全绿，PySide6/Qt6 + 纯 Python 协议栈）。
> 本文只做**决策与设计**，不写实现细节；每条都标了"要动哪几个文件"和"风险在哪"。

---

## 0. 先看这三句话

1. **「加 Rust/C++ 提升性能」这个方向不成立** —— 这个应用没有 Python 热点。
   判题的时间全花在 `g++` 编译和被测程序运行上，Python 只负责起进程和采样内存；
   界面本身就是 C++（Qt）。唯一值得写原生的地方是**雷同检测的批量指纹**，
   而那个用倒排索引 + winnowing 在纯 Python 里就是百毫秒级。

2. **「加 Rust/C++」和「支持 Windows 7」是互相打架的两件事。**
   Rust 从 1.78 起把 `*-pc-windows-*` 的最低系统要求提到了 **Windows 10**；
   Win7 目标 `x86_64-win7-windows-msvc` 只是 **Tier 3** —— 官方不构建、不测试、
   `rustup` 都装不到，要自己用 nightly 编 std。
   换句话说：为了支持 Win7 而加 Rust，等于给自己加一道最难的坎。

3. **「支持 Windows 7」和「保持现在的界面」也是打架的。**
   Qt 6 **任何版本**都要求 Windows 10 1809+（Qt 6 从未支持过 Win7）；
   Python **3.8 是最后一个支持 Win7** 的版本（3.9+ 依赖 Win8.1 才有的 API）。
   要 Win7，就得把 `Python 3.13 + PySide6` 整套换成 `Python 3.8 + PySide2(Qt 5.15)`。

→ 所以本规划把 **Win7 单独列成一个"要不要立项"的决定**（见 §8），
  其余 12 项功能**一律不动技术栈**，可以直接排期。

## 1. 加密：国密 / AES-256 可切换（含一个现存的安全缺口）

### 1.1 现状

`offline_oj/net/crypto.py` 是**纯 Python 自实现的 ChaCha20-Poly1305（RFC 8439）**，
零第三方依赖，有官方逐字节测试向量兜底（`tests/test_net_crypto.py`）。

**密钥不是协商出来的，是派生出来的**：

```
room_secret = 房间号[:口令]           # session.py:167-186
room_id     = sha256(room_secret)[:16]  # 明文 HELLO 里只发这个索引
盐          = 主机随机 16 字节（CHALLENGE 帧）
会话密钥    = scrypt(room_secret, 盐, n=2^15)   # crypto.py:242-268
```

即**预共享秘密 + 无盐派生**。`crypto.py` 自己的注释写得很诚实：房间号只有 6 位
数字，攻击者搜索空间 10^6，scrypt 让每次尝试约 350ms，在线爆破被握手限速挡住，
**但抓到一个握手帧之后可以离线爆破，多核并行下是"小时"量级**。

### 1.2 要做到"无感 + 国密级"，真正该改的是这里

"无感"现在**已经成立**（学生只输房间号）。要升级的是**密钥强度不该再依赖房间号**：

> 改成**每次开房现生成临时密钥对**的握手，房间号从此只承担"分房间 + 挡隔壁教室误入"，
> 不再承担密钥强度。这一步顺带把**前向保密**拿到手——录下今天全部流量的攻击者，
> 拿到明天的房间号也解不开今天的包。

握手三个往返，学生端依然无感（不用输任何东西）：

```
学生 → 主机   HELLO     { room_id, supported_suites: [...] }
主机 → 学生   CHALLENGE { 临时公钥, 盐, suite(主机选定), version }
学生 → 主机   AUTH      { 用主机公钥封装的材料, 我们的临时公钥 }
双方          会话密钥 = KDF(共享秘密 ‖ 双方临时公钥 ‖ 盐)
主机 → 学生   WELCOME / REJECTED
```

### 1.3 套件可插拔

`crypto.py` 抽成 `Suite` 三元组，三个实现：

| 套件名 | 密钥交换 | AEAD | 哈希 | 依赖 |
|---|---|---|---|---|
| `curve25519-chacha20` | X25519（可自实现，仅需 25519 标量乘） | ChaCha20-Poly1305 | SHA-256 | **零**（沿用现有实现） |
| `aes256-gcm` | X25519 | AES-256-GCM | SHA-256 / HKDF | `cryptography` |
| `sm2-sm4gcm`（国密） | SM2 密钥交换 | SM4-GCM | SM3 | **零**（自实现）或 `gmssl` |

**好消息**：`protocol.py:234-251` 的 `SecureChannel` 写死的 nonce=12 / tag=16
**对三者都能成立**（AES-GCM 标准 nonce 12、tag 16；SM4-GCM 的 IV/tag 长度由我们
自己定，取一样的 12/16 即可 —— GCM 结构允许），所以**帧格式不用改**，
只要换底层实现 + 握手加协商字段。

**坏消息**：`cryptography` 是编译扩展（≈8 MB，且新版不再提供 cp38/Win7 wheel），
这会直接顶掉"解压即用零依赖"和 Win7 两条底线之一。SM4 用纯 Python 自实现则零代价
—— 标准做法是**预计算 4 张 256 项 T 表**，一次查表代替四次 S-box，实测可到
2~5 MB/s，与现有 ChaCha20 同量级。（注意：T 表实现有缓存计时侧信道，但本项目的
威胁模型明确写了"面对的是同网段同学，不是国家级对手"，与现有注释一致。）

### 1.4 主机端的策略开关

```
crypto_policy: auto | require_sm | require_aes | allow_all
```

主机在房间设置里选；学生端可设偏好，**主机说了算**；不匹配 → `REJECTED` 带上原因。
`protocol.py` 的 `PROTOCOL_VERSION` +1，老客户端连新主机走 `auto` 回落到 chacha20。

**要动的文件**：`net/crypto.py`（抽 Suite + 新增 SM/X25519）、`net/protocol.py`
（握手字段 + `PROTOCOL_VERSION`）、`net/server.py:405-433`、`net/client.py:46`、
`ui/panels/exam_panel.py`（房间设置 + 不匹配提示）、`tests/test_net_crypto.py`（新增向量）。

**风险**：自己写 SM2/SM4 属于"自己写密码学"，必须**照抄国标测试向量**
（`GM/T 0002-2012` SM4、`GM/T 0004-2012` SM3、`GM/T 0003-2012` SM2），
并沿用现有 `test_net_crypto.py` 的逐字节比对风格。这是**唯一一个我不建议赶工的功能**。

## 2. 考试流程：开考时刻 / 备考状态 / 策略限制 / 不放榜 / 改名

这一组都落在 `net/session.py` + `net/server.py` + `exam_panel.py`，彼此相关，建议一期做完。

### 2.1 改比赛名称（小，立刻可做）

`ExamSession.title` 已经存在，只是没有修改入口。

- 新增 `ExamSession.rename(title)`
- 广播一帧 `EXAM`（题目与标题本来就在这个载荷里），学生端标题栏跟着变
- **不需要动 `room_id`**：它是 `sha256(房间号[:口令])[:16]`，与 `title` 无关 ——
  改名不会把已有的学生踢下线。这一点要写进注释，否则以后有人"顺手"把 title
  拼进 room_id，全教室掉线。

### 2.2 提前下发题目 → 备考状态 → 等开考指令

现状：`ExamState`（`session.py:111-124`）确实有 `PENDING/RUNNING/ENDED`，
但 `open_room()` 从不把 `starts_at` 设到未来，**PENDING 实际不可达** —— 开房即开考。

要做的：

1. `open_room(starts_at=...)`：UI 上给"立即开考 / 定时开考"两个选项
2. **备考状态**（学生端 `PENDING`）：能看题、能写代码、**不能提交**；
   编辑器的提交按钮换成"等待开考"，并在题目栏挂一个倒计时
3. 到点由主机广播新帧 `START`（**不是让学生自己看表**）
4. 主机端加「开始考试」按钮，可以提前开考（`force=True`）

**为什么必须由主机广播而不是各机自己算时间**：学生机的系统时钟不可信（时区、
对时失败、故意改表）。一旦让客户端用本地时间判定"到点了"，就同时出现了
"有人提前 5 分钟进场"和"有人永远进不去"。这条要在 README 里写明。

**要动的文件**：`protocol.py`（`START` 帧 + `MessageKind`）、`session.py`（`state()`
与 `starts_at` 语义）、`server.py`（开考定时器 + 广播 + 提交拒绝）、
`exam_panel.py` 两侧 UI、`tests/smoke_gui.py`（它是"窗口还能不能装配"的守卫）。

### 2.3 策略：限制语言 / 禁用功能

新增一个 `ExamPolicy` dataclass 挂到 `ExamSession`，**默认值就是现在全开的行为**，
所以向后兼容（沿用既有约定：`to_dict()` 只写非默认项）：

```python
@dataclass
class ExamPolicy:
    allowed_languages: tuple[str, ...] = ()      # 空 = 不限
    allow_local_run: bool = True                 # 关掉「测试运行 / 自测」
    allow_copy_out: bool = True                  # 关掉「复制代码」
    allow_resubmit: bool = True                  # 已有语义，搬进来
    allow_leaderboard: bool = True               # 见 2.4
    lock_after_submit: bool = False
```

**关键：服务端必须自己校验，不能只靠界面灰按钮。**
学生端是可以被改的（改 exe、改内存、直接发包都行），所以 `server.py` 收提交时
要再校验一次 `language in allowed_languages`，不合法就回 `REJECTED`。
UI 置灰只是"别让人白点一次"，不是安全边界。这条要单独写个测试。

### 2.4 可以选择不放榜

现在 `RoomMode`（PRACTICE / EXAM）唯一的分支就是 `leaderboard_visible()` ——
"练习实时放 / 考试全程封榜"。把它正交化成两个字段：

```
RoomMode:   PRACTICE | EXAM          # 保留，前者=练习语义
show_leaderboard: bool = True        # 新增，False 则榜单全程不出现
```

这样能表达四种组合，包括你要的"考试 + 全程不放榜"。
注意 `ExamSession` 是 `to_dict()` 落盘的 dataclass，新字段必须**只写非默认值**。

### 2.5 比赛改名 / 不放榜 / 限制语言 的界面落点

都在主机端房间设置面板：名称输入框 + 「开始考试」按钮 + 语言多选 +
功能开关组。注意项目既有的 UI 纪律：**同一屏同一个字符串只许出现一次**
（`tests/test_ui_dedup.py` 会扫描），且**页签下标一律用具名常量**
（往 `HOST_TAB_*` 中间插页会让截图脚本静默指到隔壁）。

### 2.6 考场身份与管控：进场二选一 / APP 内名单 / 离场锁屏（✅ 已实现）

用户第 15 条需求，三轮澄清后定稿：**进场方式建场时二选一**（房间号 ⇄ 账号+个人口令）；
**名单直接在 APP 里建**（不强迫老师先去画 Excel，CSV 导入只是辅助）；
**离场锁屏防窥屏**（离开座位时盖住题面与代码，回来输密码才能继续写继续看；
防拷贝/防截屏是另外的事，与本节正交）。

| 能力 | 落点 |
|---|---|
| 账号/口令/凭据规则单一真源 | 新 `credentials.py`（纯 stdlib；`core/` 不许 import `net/`，而两边必须逐字节一致 —— 不一致 = "密码对也进不去"） |
| 名单数据层（JSON 落盘 + CSV 导入导出） | 新 `core/roster.py`（utf-8-sig→GBK 兜底、表头别名、`from_rows` 把丢弃的行回报出来，绝不静默） |
| 名单编辑器（APP 内直接建） | 新 `ui/roster_dialog.py`（表格就地编辑 / 生成口令只补空的 / 导出打印条；丢弃行写底部状态栏，不弹框） |
| 进场握手合流 | `net/session.py` `EntryMode` + `resolve(index)`；`net/server.py` **查哪侧由本场设定决定，不由客户端自报** |
| 绑定选手信息 | `authenticate()` 认账号也锁设备（一人一机、一机一人）；名字由名单回填（学生自报不采信）；`bindings` 不进全班广播、只进老师档案 |
| 离场锁屏 | `LOCK/UNLOCK/UNLOCKED` 三帧；学生端盖板（`student_stack` 正文页 ⇄ 盖板页）；主机「名单」页 8 列带「锁」+ 四个监考按钮 |
| 解锁 | 校验在主机（`hmac.compare_digest`，个人口令或考场口令都行），错满 5 次只能老师放行（防在线爆破） |

几条刻意的设计（将来动这里先读这几句）：

- **进场方式不给"两种都开"**：握手第一步主机就要知道查哪一侧，那一刻还没读到
  任何学生自报的东西。让 HELLO 带"我走哪种方式"的标记 = 让客户端挑校验 = 没有校验。
- **`PROTOCOL_VERSION` 不升**：纯增量帧。升了 = 只升级老师机时全班进不来。
- **名单上的明文口令是刻意取舍**：老师要打印口令条、考前念给学生，
  `PASSCODE_NOTICE` 的警示文案全项目只此一处。
- **客户端只能锁自己**（发 `locked=False` 会被拒，否则改一下客户端=万能钥匙）；
  解锁只认显式 UNLOCK 帧，快照重连只负责"把锁捡回来"，绝不替学生解锁。
- **「离开一下」按钮只在有钥匙时亮**：盖上一块解不开的屏幕是事故不是保护。
- 测试：`tests/test_roster.py`（74 条）/ `test_net_session.py` +46 /
  `test_net_lan.py` +15（真 TCP，含爆破上限与自解锁被拒）/ `test_exam_access.py`（26 条，UI 全链）；
  `tests/smoke_gui.py` 新增 `run_access_smoke`（建名单→开房→锁屏→解锁→留档一整圈）。

### 2.7 主机端按阶段换屏：准备视图 ⇄ 监考视图（✅ 已实现）

**要解决的问题**：主机端左列是一个固定 400px 的竖列，塞了 15 个控件。开房之后其中
8 项本就冻结，却仍然占着屏幕 —— "主机端还是挤"是反复被提的体验问题。

**做法**：左列改成一个 `QStackedWidget`，两页，由已有的 `_apply_host_state(running=)`
驱动切换（它是"房间状态"的唯一写入口）：

| 页（具名常量） | 什么时候显示 | 里面有什么 |
|---|---|---|
| `HOST_SIDE_PREPARE` | 没开房 | 房间设置 / 本场限制 / 本场题目三组 + 「开启房间」 |
| `HOST_SIDE_PROCTOR` | 开了房 | 大字房间号 + 只读摘要 + 改名 + 开始考试 / 提前收卷 / 提前结束 / 复制信息 / 关闭房间 |

可视控件 15 → 8，且余下每一项在监考阶段都**真的有用**。

几条刻意的设计（将来动这里先读这几句）：

- **换屏走具名页常量**（`HOST_SIDE_*`），不写裸数字，也不用 `setVisible` 硬拼 ——
  与 `HOST_TAB_*` 同一条纪律：往中间插一页，裸数字会静默指到隔壁。
- **逐控件 `setEnabled` 的写法一个字都不改**：有六个测试（`test_exam_settings`、
  `test_o2_option`）直接断言单个控件的 `isEnabled()`。改成给整页 `setEnabled(False)`
  会让这些断言失去意义（Qt 里 `isEnabled` 不看祖先，只有 `isEnabledTo` 才看）。
- **开房前/后是两个按钮，不是同一个按钮搬家**：「开启房间」常驻准备视图、
  「关闭房间」常驻监考视图，都连 `toggle_room`。同一个按钮在两页之间搬，会让
  "它现在属于哪一页"变成要追代码才知道的事。
- **只读摘要报的是生效值，不是输入框草稿**：模式 / 进场方式 / 时长 / 题数 /
  本场限制五项，全部从 `ExamSession` 与服务端实际定下来的那份读（`_policy_text()`
  由 `_collect_policy()` 反推），不另存一份 —— 免得摘要与真正生效的策略不一致。
- **摘要用竖排，不用 `QFormLayout`**：`QFormLayout` 的字段列按单行 `sizeHint`
  定行高，`setWordWrap` 后的多行高度不被采纳；改成 HBox 也不够（值那列拿到足够
  摆下前半段的宽度就不折行，后半段越过组框边缘被裁掉）。竖排时"可用宽度"与
  "裁剪边界"重合。这条是真机截图走查抓到的，别改回去。
- **改名独占一页**：它是全程唯一还能改的设置（只是显示标签，改它不踢人）。
  监考视图里给它自己的输入框 + 按钮，不依赖准备视图那个输入框 —— 后者开房后
  已经随整页收起了。
- 测试：`test_exam_settings` / `test_exam_access` / `test_o2_option` /
  `test_exam_code_view` / `test_ui_dedup` / `test_ui_theme` 六个守卫模块全绿
  （共 115 条 + 272 subtests）；`tests/smoke_gui.py` 两条链（`run_exam_smoke`、
  `run_access_smoke`）在换屏后仍全绿。

## 3. 判题与展示

### 3.1 洛谷配色对标（确实没对上，这是清单）

现状在 `theme.py:88-100 verdict_color()` 与 `theme.py:624-634 VERDICT_TONES`：

| 结论 | 我们现在的色 | 洛谷的色 | 差在哪 |
|---|---|---|---|
| AC | `success`（绿） | `#52C41A` | 接近，可直接换 |
| WA | `danger`（红） | `#E74C3C` | 接近 |
| **TLE** | `warning`（**橙**） | `#052242`（**深墨蓝黑**） | ✗ 完全不是一个色系 |
| **MLE** | `#8a5cd6` / `#b79cf0`（**紫**） | `#052242` | ✗ 洛谷 TLE/MLE/OLE 是同一个色 |
| **OLE** | `warning`（橙） | `#052242` | ✗ |
| **RE** | `#d13438` / `#ff9a9a`（**红**） | `#9D3DCF`（**紫**） | ✗ 红紫互换 |
| **CE** | `text_muted`（**灰**） | `#FADB14`（**黄**） | ✗ |
| UKE | 无 | `#0E1D69` | 缺 |
| 未判定 | 无 | Waiting `rgb(20,85,143)` / Judging `rgb(52,152,219)` | 缺 |

**但不能照抄。** 洛谷把 TLE/MLE/OLE 都压成 `#052242`，那是**给浅色背景用的**深色；
放到我们的深色主题（`#1e1e1e` 一类）上，对比度只剩 1.1:1，等于看不见。

**方案**：给判题结论建一套**独立于语义色**的 tone，每个 tone 两套主题各一个色值：

```
[role="badge"][tone="ac"]  → 浅色 #52C41A / 深色 #6fdd3a
[role="badge"][tone="wa"]  → 浅色 #E74C3C / 深色 #ff8a80
[role="badge"][tone="re"]  → 浅色 #9D3DCF / 深色 #c79bf0   ← 紫
[role="badge"][tone="ce"]  → 浅色 #FADB14 / 深色 #ffe066   ← 黄
[tone="tle"|"mle"|"ole"]   → 浅色 #052242 / 深色 #7fb3f0   ← 同色相提亮
[tone="uke"]               → 浅色 #0E1D69 / 深色 #8fa8e8
[tone="waiting"]           → 浅色 #14558F / 深色 #4a8fd4
[tone="judging"]           → 浅色 #3498DB / 深色 #6fb3e8
```

**为什么新建一套 tone 而不是改 `success/danger`**：`danger` 还用在错误提示、
`success` 还用在"已连接"等地方；把 RE 改成紫色会连累所有红色的错误文案。

深色侧的提亮规则沿用项目既有结论：**色相不变，明度抬到可读区间；
徽标前景色按相对亮度挑，分界点 L ≈ 0.19**（这是两色对比度相等处，不是 0.5）。

### 3.2 O2 优化要"标注出来"

现在 `solve_panel.py:229` 只是一个复选框 + tooltip，判完之后**看不出来这份提交
到底是不是 O2 编的**。而 `Submission`（`session.py:310-332`）里也没有这个字段。

1. `Submission.optimized: bool = False`（`to_dict()` **只写非默认值**，向后兼容）

### 3.3 做题代码：保存到文件 / 从文件打开

写题面板（练习）与测验面板（学生端）的编辑器各加「打开…」「另存为…」，
用 `QFileDialog`，后缀按当前语言给（`.cpp/.c/.py/.java`）。

**要注意的三件事**：

- **和"未保存"标记联动**：打开新文件前要检查 `_set_dirty` 状态，脏就确认
  （项目的 UI 测试纪律里，"脏着关窗口会弹模态框，离屏环境没人点得到，会挂死"）
- **记住上次目录**：存到 `settings`，否则每次都在系统默认目录开始翻
- **编码**：一律 UTF-8 读写，显式 `encoding="utf-8"`。学生用记事本另存可能带 BOM，

### 3.4 自动联想：**已经是自动的，问题在阈值**

`widgets.py:946-948` 每次按键后 `_triggered_by()` 判断是不是标识符字符
（字母/数字/`_`/`.`），是就 `try_complete()` —— 本来就是"敲字母自动弹"，
`Ctrl+Space` / `Alt+/` 只是备用通道。

那为什么体感像"要手动开"？看 `widgets.py:588`：

```python
if not force and len(prefix) < MIN_PREFIX:   # MIN_PREFIX = 2
    popup.hide(); return
```

**要敲满 2 个字符才弹，而且一个候选都匹配不上时直接 `hide()`**
（`widgets.py:595-597`）。所以敲第 1 个字母没反应、敲了个冷门词法也没反应。

改进项（都是小手术）：

1. `MIN_PREFIX` 2 → **1**（"敲下字母就自动开启"，就是你要的那个手感）
2. 加一条**静音规则**：光标在注释 / 字符串 / 行首缩进区时不弹
   —— 阈值降到 1 之后不加这条会变得很吵
3. 扩大静态词表：现在每种语言只有几十条（`widgets.py:~300-347`），
   补上常用 STL/标准库符号与语言关键字
4. 增强动态词表：现在从全文扫标识符（`MAX_SCAN_CHARS=400_000`），
   可以再补"当前题目题面里出现的标识符"
5. 输入 `.` 后只弹成员（现在的 `_triggered_by` 已经把 `.` 算进去了，
   但 `prefix_at` 会把 `obj.mem` 整体当前缀，需要看 `_WORD_PREFIX` 的边界）

**建议先做 1 + 2 + 3 这三条**，成本很低，手感差别最大。

### 3.5 积分规则对标 NOI（第 1 期追加）

三处"跟 NOI 一样"，前两条已实现：

| 项 | NOI 的做法 | 原来的做法 | 现在 |
|---|---|---|---|
| 名次 | **同分并列**，下一名跳过（1,1,3） | 同分再比耗时/内存/提交时间，排出 1,2,3 | 同分并列；耗时只决定**显示顺序**，不决定名次 |
| 每题满分 | **逐测试点给分**，满分是各点分值之和 | 恒定 100，按通过比例折算 | 每个测试点自带 `points`（默认 10），题目满分是它们的和 |
| 等级线（一等/二等线） | 赛后按比例划 | 无 | **暂不做**，与导出一起放到第 2 期 |

**为什么"按测试点分值"是必须的**：NOI 的分数不是"过了几个点"的比例，而是
"过掉的那些点各自值多少分"的和。三个点 50/30/20 的题，只过第一个是 **50** 分，
不是 33 分。所以分值是**测试点上的属性**（`TestCase.points`），一路带到榜上：

```
TestCase.points → TestOutcome.points → JudgeReport.points_earned / points_total
                → Submission.score / possible → ExamProblemView.points
                → leaderboard_payload.max_total_score → 界面 "37/50"
```

名次算法是一个纯函数 `session.competition_ranks(scores)`：同分并列、下一名跳过，
排序只用来决定**同分之间谁先显示**（耗时 → 内存 → 提交时间）。它和"按什么排序"
是两件事，混在一起写就会变成"耗时代替分数"。

**两条给分路径必须共用一把尺子**（这里踩过一次）：

- 判题器报分值 → `score` = 通过的测试点分值之和，`possible` = 各点分值之和；
- 判题器只报通过数（**外部接入**的那种）→ 按通过比例折算，但**分母取该题的
  分值之和**，不是老的恒定 100。

第二条的分母如果继续用 100，榜上会出现 **"得分 100 / 满分 60"** 这种读不通的
行（冒烟测试当场抓到）。现在两路都是"全对 = 该题满分"，界面上得分一律写成
`37/50` 而不是光秃秃的 `37`。

**向后兼容**（沿用"默认值不落盘"的约定）：默认 10 分不写进 `problems.json`，
老题库的字节逐字不变，读回来仍是 10；`Submission.possible` 也只在非 0 时才写。
想让 5 个点的题满分 100，就把每个点设成 20 —— 测试点卡片的标题行里就有分值，
底下还有一行「合计 N 分」跟着变。

## 4. 留档、读档与导出

### 4.1 历史场次（✅ 已实现）

现状（改造前）：`ExamSession` 全在内存，**关房即清**。落盘的只有
`paths.py:119-122` 的 `submissions_dir/history.jsonl`（`repository.py:383 SubmissionLog`），
那只是**本机单人练习**的提交记录，上限 500 条，跟"一场考试"没关系。

新增 `offline_oj/core/records.py`：

```
%LOCALAPPDATA%\OfflineOJ\exams\<YYYYMMDD-HHMMSS>-<标题>\
    session.json        场次元数据（标题/模式/策略/时间/参与者/题目快照）
    submissions.jsonl   全部提交，含源码与判定（一行一份，追加友好）
    leaderboard.json    收卷时的榜单快照
    archive.json        版本号 + 各文件校验和
```

**实现时改了两处设计**：

- 目录名第二段用**标题**而不是房间号 —— 房间号是凭据，撒进文件名只会让学生机
  被翻看时多一条线索；老师认档案靠标题和时间就够了。`session.json` 里也只存
  `room_id`（`sha256(房间号[:口令])[:16]`）这个单向索引。
- 写盘策略是**先写 `.partial` 再改名**：中途崩了不会留下"半个档案"被当成正常的。
  列表页跳过 `.partial`。

- 关房时自动留档（`settings.archive_on_close`，主机端可关掉这个开关）；
  **开了又关、一个人都没进来**的场次不留空档案，否则列表会被试错塞满
- **留档绝不能把关房搞失败**：整段包在 `try/except` 里，出错只记一条日志
  （磁盘满 / 文件被占用不该让老师下课关不了房）
- 主机端新增「历史场次」页（`HOST_TAB_ARCHIVE`）：列出（按时间倒序）→
  打开回看 → 打开目录 → 删除（删除前确认，且**校验 `archive.json` 存在**才动手，
  免得误删别人）
- 「打开回看」**直接复用现成的「提交与代码」页**：`_code_items()` 在
  "进行中的这一场"和"档案"两个数据源之间切换，列表/源码/判定说明/复制那套
  刷新纪律全部沿用。回看时页顶多一行作用域提示 —— 否则两年前的提交和刚交的
  长得一模一样
- **隐私**：留档会存源码，界面上写明"这份档案包含全部学生源码"，
  并给"只存成绩不存代码"的选项（`settings.archive_keep_code`）。
  抠源码**做两道闸**：`ExamSession.archive_submissions(keep_code=False)` 抠一遍，
  `write_archive` 落盘前**再抠一遍** —— 验的是"哪一天有人忘了"
- `archive_version` 字段必备；读档遇到未知字段忽略而不是报错；
  半行坏行跳过并计数，`session.json` 缺失才算读不出来
- 目录名/标题里的 Windows 非法字符必须过筛子（`archive_directory_name`）。
  **`stamp` 也筛** —— `started.isoformat()` 是个太顺手的写法，而冒号会让
  `mkdir` 报 `WinError 123`，报的还是整条路径，看着像根目录不存在

### 4.2 导出 Word / txt / Excel / PDF

**关键决策：不引入 reportlab。** 理由：PDF 的中文要嵌字体（几 MB TTF），
不嵌就是一片方块；而 **Qt 自带 `QPdfWriter`，中文用系统字体天然正常，
零新依赖**。同理 xlsx/docx 也不用 `openpyxl`/`python-docx`
（后者依赖 `lxml` 这个编译扩展，而 `packaging/offline_oj.spec:73` 明确把 `PIL` 排除了，
reportlab 恰好依赖 PIL）：

| 格式 | 方案 | 新依赖 |
|---|---|---|
| txt / csv | 直接 `write`，UTF-8-SIG（Excel 打开中文不乱码） | 无 |
| xlsx | 手写 OOXML（就是个 zip + 几个 XML，一份表格约 150 行） | 无 |
| docx | 手写 OOXML（同上，约 120 行） | 无 |
| pdf | `QPdfWriter` + `QTextDocument`（分页、表格用 HTML 子集） | 无 |

导出内容三选一（做成对话框让老师勾）：

- **成绩单**：一行一人，列是各题得分 + 总分 + 排名
- **提交明细**：一行一次提交（时间/人/题/语言/结论/得分/耗时/内存/O2）
- **完整档案包**：上面的 xlsx + 每人一个源码文件的 zip

注意：导出**不要在 GUI 线程里同步写大文件**（几百份提交的 PDF 会卡界面），
走现成的 `win32/process.py` 子进程模式或 `QThread`；子进程一律用
`win32/process.py` 的 `popen`/`run_silent`（不弹黑窗、UTF-8 解码）。

## 5. 雷同检测（✅ 已实现）

**落点**：`core/similarity.py`（纯标准库，不 import PySide6、也不 import `net/`）
+ `ui/similarity_dialog.py`（结果对话框）+ 主机端「提交与代码」页的「雷同检测…」按钮
（这一页的数据源同时覆盖"进行中的这一场"与"打开的档案"，所以一个入口管两种场景）。
测试：`tests/test_similarity.py`（62 条）+ `tests/test_similarity_ui.py`（24 条）。

实现时比方案更具体地定下来的几条（改动这里之前先读）：

- **完全重复基于"排过版的"文本做 SHA-256**：去注释用**手写状态机**（字符串字面量里的
  `//` / `#` 不算注释 —— 正则做不对这件事）→ 行内连续空白压成一个空格 →
  C 系连行首缩进一起去掉。
  **Python 必须保留行首缩进**：缩进在那门语言里是语法，`if x:\n    y` 与
  `if x:\ny` 归一成同一个东西就是误报，而这一层承诺零误报。
  代价是"把 4 空格缩进改成 2 空格"不会判成完全重复（落到高度相似那一层，仍是 100%）。
- **BOM / CRLF 不算差异**：学生用记事本另存出来的就是带 BOM 的 CRLF。
- **小样本不扣骨架**（不足 3 份提交）：两份里"两份都有"的公开度是 100%，
  照比例扣会把两人**真正共享**的那段也扣掉 —— 抄的人被判 0，是最坏的一种错。
  代价是公共模板会把相似度整体抬高，所以报告里有一条 note 明说这件事
  （"这几道题样本太少，没能扣除公共模板，请只当作线索"）。
- **一人一题只取最高分那次**做代表（同分取更晚的），并在报告里写明合并了多少份 ——
  老师会数"我明明收了 40 份"。
- **跨题聚合按"人"（设备号）聚合，不按提交编号**：同一个人在不同题目里的编号本就不同，
  按编号聚合会让"甲在两道题都与乙像"变成两条记录。
- **性能**：400 份提交 / 1.3 万行 ≈ **2.0 秒**；200 份"全班互抄"0.43 秒
  （倒排索引只比至少共享一个指纹的那些对）。纯 Python 够用，**不需要 Rust**。
- **界面措辞**：全文不出现"抄袭"；复核提示常驻、不可折叠；「完全重复」与
  「高度相似」分开列且措辞不同；口径说明（扣了什么、哪些题没扣）就摆在结果下面。

以下是原方案的两个层次（分开做、分开报）：

### 5.1 完全重复（确定性的，零误报）

源码归一化后取 SHA-256：

1. 去 BOM、统一换行
2. 去注释（按语言词法，不能简单正则 —— 要把字符串字面量里的 `//` 排除）
3. 去行首尾空白、去空行
4. 剩下的**逐字节**哈希

哈希相同 = 除了注释和空白之外一字不差 → 相当于抄。

### 5.2 高度相似（启发式，必须人工复核）

用 **winnowing / fingerprint（MOSS 那一路）**：

1. 词法归一化：把标识符、数字、字符串字面量统一替换成占位符
   （这样"改个变量名"躲不掉）
2. 滑窗取 k-gram（k = 语言相关，C++ 取 15 左右）哈希
3. 按窗口 w 取每个窗口的最小哈希 → 指纹集合
4. 两两算 Jaccard 相似度

**性能**：几百份提交、每份几千 token、指纹集合几百个 —— 用**倒排索引**
（指纹 → 出现在哪些提交）只比有交集的那些对，实际是近似线性。
纯 Python 完全够，**不需要 Rust**（这就是 §0 第 1 条的具体落点）。

**必须防的误报**：

- 只在**同一道题**内比较（跨题比没有意义）
- **扣除模板骨架**：C++ 的 `#include <bits/stdc++.h>`、`int main()`、
  快读模板、Java 的 `BufferedReader` 那一段，所有提交都长一样。
  做法是对同一题所有提交求"公共指纹"，公开度超过阈值（如 >80% 提交都有）
  的指纹先扣掉，再算相似度。**不做这一步，第一版报告会全是 90%+**
- 只报**同一题内**、且**两人之间最高的那一对**，避免一个人和 5 个人都 80%

**报告形式**：相似度矩阵（热力图）+ 最高的 N 对 + 每对的**并排 diff**
（按行比对，高亮相同与不同的行段）。放在主机端，建议做成**独立对话框**
而不是新页签 —— 它是"老师主动发起的一次分析"，不是常驻视图。

- **页签下标一律具名常量**（`TAB_*` / `HOST_TAB_*` / `STUDENT_TAB_*`）；
  刚踩过一次：插一个新页把截图脚本里的 `setCurrentIndex(2)` 静默指到隔壁，
  脚本不报错、图看着也正常
- **同一屏同一字符串只许出现一次**（`tests/test_ui_dedup.py`）、
  **快捷键不许撞车**（`tests/test_ui_shortcuts.py`）、
  **间距用 `theme.py` 令牌**（`tests/test_ui_theme.py`）
- **落盘结构加字段必须向后兼容**：`to_dict()` 只写非默认项，测试断言**字段集合**
- **源码只上行不下发**：`Submission.to_dict()` 不含 `code`，
  `test_net_lan` 与 `test_net_session` 有两条守卫，动任何出站载荷就会红
- **凡同步等待都要有*时间*上限**，超时即作废连接（拿一次 2 小时 49 分的挂死换来的）
- 界面走查**必须真机截图**（`QT_QPA_PLATFORM=windows`），离屏没有中文字体
- 跑全量**不要在同一个 turn 里做大清理**（沙箱删除预算按轮次累计，会误报一堆
  fixture setup ERROR）—— 这条已写进工作区笔记

## 8. 悬而未决：Windows 7

### 8.1 三条硬约束（都是官方文档，不是配置问题）

| 组件 | 支持 Win7 的最后版本 | 之后的版本 |
|---|---|---|
| Qt | **Qt 5.15**（Qt 6 从未支持 Win7） | Qt 6：Windows 10 1809+ |
| Python | **3.8**（SP1 起） | 3.9+：Win8.1+（依赖 `GetSystemTimePreciseAsFileTime` 等） |
| Rust | **1.77 及更早**（用 `*-pc-windows-*`） | 1.78+：Windows 10；Win7 目标降为 Tier 3，rustup 装不到 |

### 8.2 三个选项

**A. 不做（推荐）**

成本 0。理由：Win7 于 2020 年 1 月终止支持，到现在已 6 年无安全更新；
而且跑 Win7 的机器通常很旧，**判题本身（g++ 编译）在那台机器上就会先慢到不可用**
—— 界面能起来了，交一份 C++ 等 8 秒，体验仍然是废的。

**B. 双轨构建：Python 3.8 + PySide2(Qt 5.15) 的 Win7 版**

保持一套源码，UI 层收敛到一个 `ui/qt_compat.py` 薄适配层，另出一个 Qt5 后端。
代价：

- 6 个面板约 5000+ 行 UI 代码要过一遍（PySide2/PySide6 的枚举访问、
  `Qt.UserRole` vs `Qt.ItemDataRole.UserRole`、`exec()` vs `exec_()` 等）
- **同时维护两套解释器 + 两套打包链**（PyInstaller 要退到 5.x）
- Python 3.8 已 EOL，`psutil`、`cryptography` 等依赖版本要钉死
- 一旦做 §1 的 AES 套件，`cryptography` 在 Win7 上基本不可用 → 只剩国密一条路

**我的判断**：除非能确认教室里有确切数量的 Win7 机器，否则不值。

**C. 先探针再决定（最务实）**

写一个 20 行的脚本，让每个学生的机器跑一次、把 `OS 版本 + 位数 + 是否装 VC 运行库`
汇总回来。**先知道有几台**，再谈要不要为它们付 B 的代价。这个探针本身半小时能做完。

### 8.3 明确不建议的

**不要为了"提升性能"引入 Rust/C++ 原生模块。** 收益接近零（没有 Python 热点），
代价却是：构建链从 `pip install` 变成"每平台装 Rust 工具链 + 编译"，
安装包变大，**并且把 Win7 从"难"变成"几乎不可能"**（Tier 3 目标需要自己编 std）。
唯一有理由写原生的雷同检测，用倒排索引做完之后是百毫秒级，也不需要原生。

**唯一例外**：如果将来题库规模到"几万份提交跨场次比对"，再把
`core/similarity.py` 的指纹计算换成一个 200 行的 C 扩展（TDM-GCC 就能编，
和现有校验器工具链一致），那时才有意义。
